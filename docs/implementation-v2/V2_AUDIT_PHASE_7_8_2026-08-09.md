- **V2-071 In-memory working copy and dirty state** — all 6 items left `[x]`. Read
  `webapp/src/v2/repositoryWorkingCopy.ts` in full: `createRepositoryWorkingCopyStore` holds
  `baseline`/`working`/`dirty` only in a closure; the only mutators are
  `applyContentChange`/`applyImport` (dirty), `markSaved` (clear dirty, new baseline),
  `discardChanges` (revert to baseline), `replaceWorkingCopy` (non-dirtying replacement).
  Package selection, sends, cancellation, snapshot deletion, and UI-preference changes have
  no corresponding method at all, so they cannot dirty the store — confirmed by inspection,
  not just the module's own doc comment. `webapp/tests/v2-repository-working-copy.test.ts`
  (11 tests) re-run in isolation, passing. "Preserve a live dirty working copy across in-tab
  reauthentication" is exercised concretely (not just architecturally) by
  `webapp/tests/v2-app-v2.test.tsx`'s `"session expiry drops back to Sign In without
  discarding the working copy"` test: `AppV2`'s `ready` state (holding the store) is never
  reset by the `subscribeUnauthorized` handler that drops the phase back to `"signin"`; only
  `AuthenticatedShell` unmounts/remounts, and the hash route survives that because
  `window.location.hash` is browser state, not React state.
