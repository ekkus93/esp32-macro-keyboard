**Phase 1 exit gate — "No production route or repository serializer still
depends on a v1 shape."** Left **unchecked** — this is not true. Verified
directly:

- `webapp/src/types/models.ts` still defines the retired v1 shape, including
  `revision: number` (optimistic-concurrency/ETag field) and
  `activePackageId: string | null` — exactly the two things
  `V2_MIGRATION_MAP.md` §8 and CLAUDE.md say were deleted from firmware and
  are not part of the v2 repository root (`docs/SPEC_V2.md` §8.2 permits only
  `format`/`schemaVersion`/`packages`).
- `webapp/src/api/routes.ts` (a production module, not a test) imports and
  uses these v1-shaped types (e.g. `SettingsUpdate.expectedRevision`).
- Live, hash-router-reachable production pages (`MacroLibraryPage`,
  `SettingsPage`, `PackageManagementPage`, `PackageSelectionPage`,
  `PackageOperationsPage`, `MacroEditorPage`, execution pages, per
  `webapp/src/App.tsx`) still import from `webapp/src/types/models.ts`.
- The genuinely-migrated `webapp/src/v2/*` contract layer (verified correct
  and complete for V2-010/V2-011 below) coexists with, but has not replaced,
  this v1-shaped stack in the live route tree.

This is real, current-tree behavior, not a stale citation — confirmed by
direct file reads of `webapp/src/types/models.ts`, `webapp/src/api/routes.ts`,
and `webapp/src/App.tsx`'s live route wiring. Per the task's out-of-scope
rule, no code was changed to fix this; it is reported here for follow-up in a
later phase (this is exactly the kind of migration residue Phase 14
